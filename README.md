## Project Overview

A Czech digital bank wants to identify customers at elevated risk of churning before they become inactive. This project builds a supervised binary classification pipeline that predicts whether a bank account will go **inactive (zero transactions) in 1998**, using only behavioral and demographic information from the preceding observation window (1993–1997).

The model outputs a **churn probability (0–1)** and a **risk tier (Low / Medium / High)** to help the retention team prioritize outreach.

---

## Problem Definition

| Item | Definition |
|---|---|
| **ML Task** | Supervised binary classification |
| **Unit of prediction** | One bank account |
| **Churn label** | `1` if account has zero transactions during 1998-01-01 → 1998-12-31 |
| **Observation window** | 1993-01-01 → 1997-12-31 (all features built here) |
| **Labeling window** | 1998-01-01 → 1998-12-31 (label constructed here — never used as a feature) |
| **Primary metric** | ROC-AUC (threshold-independent, robust to class imbalance) |
| **Supporting metric** | PR-AUC, Recall (false negatives are costlier than false positives) |

## Features

The model uses 24 account-level features, all computed **exclusively from the observation window** (1993–1997):

| Group | Features |
|---|---|
| **Transaction** | `trans_count`, `trans_freq_monthly`, `avg_trans_amount`, `std_trans_amount`, `credit_count`, `debit_count`, `credit_ratio` |
| **Balance** | `avg_balance`, `std_balance`, `min_balance`, `max_balance`, `final_balance`, `balance_trend`, `months_since_last_tx` |
| **Account** | `tenure_months`, `statement_freq_code` |
| **Product** | `has_loan`, `has_card`, `order_count` |
| **District** | `region_code`, `avg_salary`, `unemployment_rate_96`, `urban_population_ratio` |

## Evaluation

All final metrics are computed on the **frozen test set** (never seen during training):

- **ROC-AUC** — primary metric (threshold-independent)
- **PR-AUC** — supporting metric (accounts for class imbalance)
- **Calibration plot** — checks that predicted probabilities are reliable
- **Confusion matrix** — error breakdown
- **Feature importance** — model interpretability
- **Slice evaluation** — per-region and per-tenure-band ROC-AUC
- **Error analysis** — top false negatives and false positives

## Limitations & Responsible AI

### Known Limitations

1. **Self-defined churn label:** The churn label (account inactivity in 1998) is a proxy constructed from the data, not a verified ground truth. Results should be interpreted with this in mind.

2. **Dataset scope:** The Berka dataset covers 1990s Czech banking. It is not representative of modern digital banking, mobile apps, or Central Asian markets. The model should not be applied to other contexts without revalidation.

3. **Sample size:** ~4,500 accounts after exclusions is a modest dataset for a three-way train/val/test split. Estimates of model performance may have higher variance than on larger datasets.

4. **Geographic bias:** Some Czech districts have very few client records, making district-level performance estimates unreliable for those regions.

5. **Temporal stationarity:** The model was trained on 1993–1997 behavior to predict 1998 inactivity. Behavior patterns may shift in a real deployment setting, requiring periodic retraining.

### Prohibited Uses

- **Do not use** this model to automatically close or freeze accounts
- **Do not use** as the sole basis for denial of services
- **Human review is required** before acting on any High-risk prediction
- **Do not apply** to non-anonymized customer data without explicit legal and privacy review

### Fairness Considerations

District-level aggregation may introduce geographic bias. Model performance is evaluated by subgroup (region, tenure band) to identify disparities. Groups with fewer than 20 test samples are excluded from slice evaluation due to statistical unreliability.

### Privacy

All training data is fully anonymized (Berka Dataset, PKDD'99). No real customer PII is used or stored in this project.
