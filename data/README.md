## How to Download the Berka Dataset

1. Go to: **https://www.kaggle.com/datasets/marceloventura/the-berka-dataset**
2. Click **Download** (free Kaggle account required)
3. Unzip the downloaded archive
4. Copy all `.asc` files into `data/raw/`

The `data/raw/` directory is listed in `.gitignore` and will **never be committed** to the repository.

## Dataset Description

**Source:** PKDD'99 Financial Discovery Challenge  
**Original publisher:** Petr Berka and Jan Rauch, Prague University of Economics  
**License:** Public, anonymized, released for academic research use  
**Time period:** 1993–1998  
**Geography:** Czech Republic (anonymized)

### Tables

| File | Rows (approx.) | Description |
|---|---|---|
| `account.asc` | 4,500 | Bank accounts with open date, district, statement frequency |
| `trans.asc` | ~1,000,000 | All debit/credit transactions with date, amount, running balance |
| `loan.asc` | 682 | Loans issued to accounts with date, amount, duration, status |
| `card.asc` | 892 | Credit/debit cards issued to dispositions with issue date |
| `client.asc` | 5,369 | Clients with birth number (encodes DOB and gender) |
| `disp.asc` | 5,369 | Maps clients to accounts (OWNER or DISPONENT role) |
| `order.asc` | 6,471 | Permanent standing orders (recurring payments) |
| `district.asc` | 77 | District-level demographic data (population, salary, unemployment) |

### Key Relationships

```
district ←── account ←── disp ──→ client
                │
                ├──→ trans
                ├──→ loan
                └──→ order ←── (via disp) card
```

### Date Encoding

All dates in the Berka dataset use **Czech YYMMDD format** (6-digit integer):
- `960101` → 1996-01-01
- `client.birth_number` encodes gender: if month > 50, subtract 50 to get month; client is female

### Known Limitations

- Dataset covers 1993–1998 Czech banking — not representative of modern digital banking
- District data is aggregate-level, not individual-level
- No direct "churn" label exists — churn is self-defined as account inactivity in 1998
- ~5,300 clients is a modest sample size for a three-way split
- Some district columns contain `?` for missing values (handled by `data_loader.py`)

## Temporal Design for This Project

```
All Berka Transactions (1993–1998)
        │
        ▼
┌─────────────────────────┬──────────────────────┐
│  OBSERVATION WINDOW     │   LABELING WINDOW    │
│  1993-01-01 → 1997-12-31│  1998-01-01 → 1998-12-31│
│                         │                      │
│  → All features built   │  → Churn label built │
│    from this window     │    from this window  │
│  → NO label info used   │  → NOT used in feats │
└─────────────────────────┴──────────────────────┘
```

**Churn definition:** An account is labeled `churned = 1` if it records **zero transactions** during the labeling window (1998-01-01 to 1998-12-31).

**Exclusion criterion:** Accounts with fewer than 12 months of history in the observation window are excluded to avoid censoring bias.
